# Firmware Architecture & Embedded Logic Overview – Home Heating IoT

🇮🇹 *Per la versione in italiano, clicca [qui](overview.it.md).*

This section outlines the distributed firmware architecture, core operational layers, and execution logic running across the Espressif ESP8266 and ESP32 microcontroller arrays within the Home Heating IoT ecosystem.

The embedded source codebase is modularly structured according to specific functional hardware roles:
*   **Ambient Thermostat Terminals (ESP8266 / ESP32):** Measure localized environmental telemetry, render graphical human-machine interfaces (HMI), calculate room thermal bounds, and push call requests to the central data tier.
*   **Hydronic Manifold Actuators (ESP8266):** Periodically poll the centralized persistence cache and drive high-voltage relays controlling zone electrovalves.
*   **Central Plant Boiler Controller (ESP8266):** Aggregates distribution load matrices and securely manages centralized pump circulation and burner ignition loops.
*   **Biomass Hybrid Stove Interface (ESP8266):** Monitors water jacket thermal curves to assert systemic high-priority heat sourcing flags.

---

## 1. Core Firmware Design Patterns

Every embedded firmware module deployed within the local network shares a standardized set of programmatic traits:
*   ✅ **Always-On Wi-Fi Resilience:** Non-blocking asynchronous network stack handling automated router re-connections.
*   ✅ **Decoupled Architecture:** Communication routed through lightweight endpoints mapping directly to the local Raspberry Pi server.
*   ✅ **High-Speed Execution:** Highly optimized single-row data transactions minimizing loop execution bottlenecks.
*   ✅ **Edge Diagnostics:** Compact serial UART and transactional logging engineered for non-intrusive runtime debugging.
*   ✅ **System Hardening:** Active hardware Watchdog Timers (WDT) preventing system freezes or indefinite thread stalls.
*   ✅ **Fast Boot Optimization:** Rapid startup routines featuring automated sensor validation and hardware self-checks.

### Extended Capabilities for ESP32 Architectures:
*   ✅ **FreeRTOS Multitasking:** Concurrent task execution split deterministically across micro-second execution cores.
*   ✅ **Premium HMI Layers:** Highly responsive capacitive touchscreen updates completely isolated from network thread delays.
*   ✅ **Multi-Sensor Data Fusion:** Simultaneous querying of BME280/MQ-135 sensors tracking Temperature, Humidity, CO₂, and TVOC variables.

## 2. Server Interaction Stack

Network communication between the distributed edge microcontrollers and the central Raspberry Pi single-board computer is handled via optimized, lightweight network endpoints:
*   Standardized HTTP GET/POST payload transactions.
*   Localized PHP application scripts that parse URL parameters directly into structured SQL queries.
*   Lightweight query argument syntax (e.g., `room=pt_soggiorno&temp=21.5`).
*   Fast, raw text or minimized JSON string payload responses.

### Operational Endpoint Examples:
*   `GET /update_temp.php?room=pt_soggiorno&temp=21.3&hum=45` (Appends rolling micro-climate time-series telemetry).
*   `GET /get_warming_state.php?room=pt_soggiorno` (Queries immediate, active room scheduling goals).

## 3. Persistent Data Exchange Models

### Ambient Thermostat Nodes transmit:
*   A 10-minute calculated rolling average of localized temperature and relative humidity metrics.
*   Immediate target heating call status bits (`0 = System Idle`, `1 = Call for Heat`).
*   User-defined physical override indicators (`Normal`, `Forced ON`, `Forced OFF`).
*   The active algorithmic operating mode (Standard Schedule, *Extra Heating* optimization, or Biomass source).
*   Local micro-second runtime clock sync variables.

### Manifold Actuator Nodes pull:
*   Flat column status fields cached inside the single-row `termostat_warming_request` lookup index.
*   Global auxiliary heating protection flags recorded within the `heating_state` ledger.

## 4. Node-Specific Operational Logic

### 4.1 Compact Thermostat Modules (ESP8266)
*   Queries environmental ambient sensors using basic sequential polling.
*   Flushes graphical screen buffers to drive standard 1.8" SPI display layouts.
*   Pushes calculated telemetry data blocks to the server precisely every 10 minutes.
*   Executes immediate, event-driven network calls as soon as local room target state shifts occur.
*   Computes smooth localized averages over rolling raw measurement sets.
*   Handles hardware external interrupts generated by physical tactile navigation buttons.

---

### 4.2 Premium Touch Terminals (ESP32 via FreeRTOS)
The embedded application code relies on concurrent, decoupled threads split by priority constraints to guarantee high availability:
*   **`Task_Sensors` (High Priority):** Handles high-frequency analogue and digital polling lines to secure stable environmental tracking.
*   **`Task_Display` (Medium Priority):** Refreshes graphical interface assets, rendering smooth charts and monitoring touch inputs.
*   **`Task_Logic` (Medium Priority):** Computes thermal hysteresis, scheduling algorithms, and safe temperature boundaries.
*   **`Task_Network` (Low Priority):** Manages asynchronous Wi-Fi handshakes and remote transactional endpoint calls without blocking core firmware loops.

---

### 4.3 Manifold Actuator Clients (ESP8266)
*   Regularly queries the high-speed `termostat_warming_request` single-row database cache view.
*   Toggles low-voltage transistor arrays driving high-voltage mechanical distribution relays.
*   Updates the verified structural execution matrix back into the central storage layer.
*   Enforces strict **90-second mechanical delay timeouts** to absorb slow manifold valve responses and protect pumps from cavitation.

---

## 4.4 Central Boiler Plant Node
*   Energizes the high-volume primary manifold recirculation distribution pump upon detecting active room calls.
*   Executes safe burner ignition routines following a **30-second fluid pre-circulation stabilization timeout**.
*   Systematically cross-references fields inside `heating_state` and `zone_status` tables.
*   Implements software-hardened dampening constraints to completely suppress rapid compressor short-cycling.

---

## 4.5 Biomass Thermo-Stove Monitor Node
*   Continuously samples water jacket thermal expansion loops using immersion sensors.
*   Updates priority energy availability records directly inside the database layer.
*   Asserts global room scheduling adjustments to evenly distribute high-temperature biomass energy across manifolds.
*   Protects interior spaces from structural overheating by enforcing a strict **22°C environment ceiling**.
